# 数门大冒险 MaxGate · 产品需求文档

| 项 | 内容 |
| --- | --- |
| 产品名 | 数门大冒险（MaxGate） |
| 版本 | v0.1（原型 + 架构基线） |
| 平台 | 网页；桌面与手机。手机以竖屏为设计基准 |
| 模式 | 无限模式（单人） |
| 排名 | 仅本地缓存个人纪录；在线排行不做，但数据可迁移 |

本文定义「做什么、不做什么、怎样算做对」。实现约束见 [ARCHITECTURE.md](./ARCHITECTURE.md)，数值阶梯见 [DIFFICULTY.md](./DIFFICULTY.md)。

---

## 1. 背景与目标

玩家要的不是又一个纯跑酷，而是**跑酷节奏 + 限时选最大数**。压力来自三件事同时发生：门在靠近、公式要算、身体要移到正确泳道。

### 1.1 要达成

1. 10 秒内能听懂规则并开始玩。
2. 桌面键盘与手机滑动都能完整打完一局。
3. 题目看起来随机，判定永远以数学求值为准，且每组门只有一个正确答案。
4. 难度平缓上升：先是差值很大的整数，再把四则（含 `3×2-4`）打很久；加泳道时回退题型。三角与根号很晚才出现。
5. 个人最好成绩留在本机，刷新页面还在。以后若做在线榜，不必改游戏内记录结构。

### 1.2 明确不做（v0.1 / v1）

- 在线账号、全球/好友排行、反作弊服务端。
- 多人对战、房间、观战。
- 商店、内购、广告。
- 肉鸽三选一、局内加命道具（只预留规则口子）。
- 强制使用 Three.js。3D 是可选皮肤，不是玩法前提。

## 2. 用户与场景

| 用户 | 场景 | 成功标准 |
| --- | --- | --- |
| 通勤时的手机玩家 | 竖屏单手，30–90 秒一局 | 滑动跟手，字足够大，误触少 |
| 桌面短休 | 键盘左右，想刷个人纪录 | 手感稳定，结算后能立刻再来 |
| 后续开发者 | 加题型、加渲染、加线上榜 | 改一处模块，不重写整局循环 |

## 3. 核心玩法

### 3.1 一句话

在限时窗口内，把角色移到当前门组中**求值最大**的那条泳道。

### 3.2 实体

| 实体 | 说明 |
| --- | --- |
| 角色 | 永远在某一条泳道上，不能停在两门之间 |
| 泳道 | 2–4 条平行道。数量由难度段决定 |
| 门组 | 一次判定对应的一组并排门，每门一个表达式 |
| 决策窗口 | 门组从出现到判定线的时长。到点即结算当前泳道 |
| 生命 | 开局 3 条。错误或超时等价错误，-1 |
| 分数 | 通过一扇门 +10。本版无连击加成 |

「超时」不是第三种结果：窗口结束时用角色所在泳道做对错判断。因此开局必须站在一条合法泳道上（默认最左或居中偏左）。

### 3.3 单局循环

```text
主菜单
  → 开局（命=3, 分=0, 已过门=0, 段位=1）
  → 生成门组（保证唯一最大）
  → 接近 + 接受左右输入
  → 到达判定线
        ├ 所在门为最大值 → +10，已过门+1，门闪烁后继续
        └ 否则 → 生命-1
  → 生命>0 则生成下一门组
  → 生命=0 → 写入本地纪录 → 结算页
```

允许在结算页「再来一局」或回菜单。排名页只读本地数据。

### 3.4 输入

| 设备 | 映射 | 备注 |
| --- | --- | --- |
| 键盘 | `ArrowLeft` / `KeyA` 左移一条；`ArrowRight` / `KeyD` 右移一条 | 按一次一格，可连按 |
| 触控 | 水平滑动超过阈值换道 | 竖屏；忽略明显的纵向滑动 |
| 鼠标 | 不作为核心操作 | 菜单按钮可点 |

换道有短位移动画，但**判定只看逻辑泳道下标**，不看动画是否播完。

## 4. 判定与正确性

### 4.1 唯一正确门

对门组中每个表达式求实数值。设最大值为 `M`。必须满足：

- 恰好一扇门的值与 `M` 的差 `< 1e-9`；
- 其余门与 `M` 的差 `≥` 当前段位要求的最小区分度（见难度文档）。

不满足则在玩家看见之前重生成。玩家侧永远不出现「两个一样大」。

### 4.2 题目形态（产品语言）

| 阶段感 | 玩家看到的例子 | 本质 |
| --- | --- | --- |
| 一眼能比 | `50` vs `3` | 整数 |
| 两步加减 | `3+2` vs `27-18` | 加减 |
| 两步四则 | `3×2-4` vs `8+5×2` | 先乘除后加减，可占很多段 |
| 要算一下 | `(3+2)×4` vs `36÷3` | 乘除与括号 |
| 符号干扰 | `-3+8` vs `5×(-2)` | 负数 |
| 特殊值 | `2×sin(90°)+3` vs `(2+3)×cos(60°)` | 三角嵌在四则里 |
| 无理但可估 | `√16+3` vs `3²-5` | 乘方、根号也带四则 |
| 以后 | `2×i²+4` vs `i²+3` | 复数落到实数再做四则（`i² = -1`） |

展示用 `×` `÷` `√` `²` `°`，不用编程语法。求值不用 `eval`。

### 4.3 随机但可复现

每一局有一个 `seed`。门组序列由种子与门序号决定。这是为了：

- 本地调试同一局；
- 以后线上榜可以抽查「这个分数对应的题是否合法」。

玩家不需要看见种子，结算记录里要存。

## 5. 生命、分数、结束

| 规则 | v0.1 | 后续开口 |
| --- | --- | --- |
| 生命 | 固定 3，无上限变化 | 道具 +1（上限 5）；肉鸽选「护盾/加命」 |
| 扣命 | 选错或窗口结束时不在最大门 | 可加「护盾抵一次」 |
| 得分 | +10 / 门 | 可加剩余时间奖励、连对奖励 |
| 结束 | 生命到 0 | 可加「残局结算动画」 |

本版**不**因为撞墙或掉出跑道扣命。只有选错门这一种失败。

## 6. 难度（产品层）

前 **5** 题仅作为规则教学，第 6 题起每 10 题提升一段。开局可选「轻松 / 经典 / 冲刺」，三种节奏共享题型阶梯，但使用不同的时间窗、数值间隙和起始题型。第 3 / 第 4 道进场时回还时间与区分度，再逐步加入括号、三角、根号与遮挡。

曲线必须「前期一眼能过、中期靠四则和括号变深、加道时先松后紧」。详细数值以 [DIFFICULTY.md](./DIFFICULTY.md) 为准。改曲线只改配置，不改玩法代码。

## 7. 排名

### 7.1 现在：本机个人榜

- 存在 `localStorage`，key 稳定，带 schema 版本号。
- 每局结束追加一条纪录：分数、过门数、最高段位、时间、种子、客户端版本。
- 展示：按分数降序，分数相同按过门数、再按时间。
- 保留最近 N 条（建议 50），避免无限膨胀。
- 本机生成一个稳定 `playerId`（UUID），为以后上传做身份锚点。昵称本版可空。

### 7.2 以后：在线榜（只设计，不实现）

同一条 `RunRecord` 经 `RankingAdapter.submit` 上传即可。远程侧建议字段：

- `playerId` / 可选账号 id
- `nickname`
- `score` `doorsPassed` `maxStage` `seed` `endedAt`
- `clientVersion`
- 可选 `checksum`（种子 + 规则版本的校验，防随手改分）

游戏内核只依赖接口，不依赖 HTTP。v0.1 的实现是 `LocalRankingAdapter`。

### 7.3 隐私

本版数据不出本机。文档与 UI 不承诺云同步。若以后上传，需要单独的同意与隐私说明。

## 8. 界面与适配

### 8.1 页面

| 界面 | 要素 |
| --- | --- |
| 主菜单 | 标题、一句规则、开始、个人纪录、操作提示 |
| 对局 HUD | 生命、段位、分数、已过门数；门面公式为主视觉 |
| 结算 | 本局分数 / 过门 / 段位；是否进入本机前三的提示 |
| 纪录 | 有序列表；空状态文案 |

对局中不弹复杂设置。暂停不是 v0.1 必做（手机切后台由浏览器暂停 rAF 即可）。

### 8.2 适配

- 画布铺满可视区域，逻辑坐标按竖屏 9:16 设计，桌面居中留边。
- 字号随门的远近缩放，到达判定前必须可读。
- `viewport-fit=cover`，避开刘海与底部手势条。
- 不依赖横屏。若用户横持，仍按竖屏构图并提示「竖屏更佳」（实现可选）。

### 8.3 表现风格（非绑定美术）

黄昏石径、门楣数字偏金。角色用可读剪影即可。第一版允许极简几何，不阻玩法验收。

## 9. 技术选型（产品约束）

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 语言 | TypeScript | 表达式 AST 与规则需要类型 |
| 构建 | Vite | 本地秒开，静态部署简单 |
| 默认渲染 | Canvas 2D | 竖屏、低端机、无额外包 |
| 可选渲染 | Three.js 实现 `IRenderer` | 仅当 2D 表达不够 |
| 后端 | 无 | 无在线榜 |
| 求值 | 自研 AST | 禁止 `eval`，保证可测 |

## 10. 验收标准（v0.1）

1. 桌面与手机都能从菜单进入、打完、看到结算。
2. 前 10 门是大差值整数（间隙 ≥ 20）；前 140 门只有 2 道；括号在约 90 门以独立高原进场；前 10 门不出现三角、乘方、根号。
3. 任意生成的门组，人工验算后最大门与引擎判定一致。
4. `2√2` 与 `3` 的比较结果为 `3` 更大。
5. 错一次掉一命，三次结束；对一次 +10。
6. 第 11、21 扇门能感觉到变难或变快（窗口或题型变化）。
7. 刷新页面后个人纪录仍在。
8. 单元测试覆盖求值与「唯一最大」不变量。

## 12. 风险

| 风险 | 应对 |
| --- | --- |
| 公式生成出两个一样大或几乎一样大 | 生成后校验，失败重掷；段位带最小间隙 |
| 手机字看不清 | 近处放大；复杂式子限制项数 |
| 三角/根号劝退 | 严格锁在后段；只用能口算的特殊值 |
| 以后改渲染把规则改坏 | 玩法只输出 `FrameSnapshot`，渲染只读 |
| 本地分被改 | 接受（本机游戏）；上线后再加种子校验 |
